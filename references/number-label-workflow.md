# 皿盖编号、处理对应和一键改名

用于皿盖上写数字编号、运行时再填写处理全名的实验。原来的规范文件名、手填清单及 CSV 测量流程仍可直接使用。

## 编号和重复的含义

- 编号是**本批实验的处理代号**，例如 `1＝吡噻菌胺`、`2＝丙环唑`、`3＝CK`。支持 `11` 等多位编号；`01` 和 `1` 保留为不同编号，不做自动合并。
- 一个编号对应完整处理条件。需要区分药剂浓度时，可填写 `吡噻菌胺 100 mg/L`，另一浓度使用另一编号。
- 皿盖 `1-2` 表示处理 `1` 的重复 `2`。软件把处理编号和重复号分开保存。
- 只写 `1` 可以确定处理，不能确定具体培养皿。重复号可留空，软件保留为未知并用图片标识防止文件名冲突；不把导入顺序推断成生物学重复。
- 同一培养皿复拍时，重复号保持不变，不能作为新增独立重复。相同处理编号和重复号的冲突需核对后再执行改名。
- CK 在本批对应表中明确填写为 `CK`。不同实验分开建立对应表和清单，分别使用各自 CK。

## 软件操作

1. 选择原始照片文件夹，填写本批实验名称、菌株/类别。
2. 在“编号—处理名称”对话框中填写对应表，可增加多位编号，也可修改已有处理全名。
3. 运行数字识别。自动读号仅填入候选，仍是未确认状态；也可直接为每张图片选择编号、输入重复号。
4. 对照缩略图核对。看不清时打开大图、框选编号区域后重试，或手动修改；确认正确后勾选确认。确认一批有效分配时也可使用界面的批量确认操作。
5. 查看改名预览。默认使用“一键改名（生成副本）”，原照片保留在原位置。需要直接修改原文件名时，选择“直接改名”，核对预览后执行。
6. 软件保存 `plate_manifest.csv`、`mapping.csv` 和事务记录。使用该清单进入原有测量、人工复核及结果导出流程。改了对应表后重新核对受影响的分配，避免旧确认套用新药名。

直接改名保留撤销入口。撤销前如果文件已被移动、修改或同名文件占用了原位置，先处理冲突，避免覆盖其他文件；生成副本的操作保留输出与记录，不通过撤销删除图片。

## 数字识别的边界

此版本加入数字 OCR 候选读取；尚无这位用户在透明皿盖上实际手写数字的准确率验证，不能用通用 OCR 指标代替本实验场景准确率。数字结果和置信分数不等于人工确认；未知、模糊或多个候选不能强行映射到当前处理编号。

拍摄时让编号写大、位置和朝向尽量固定、完整入镜，避开高光和冷凝水。取下的透明皿盖可放在白色哑光垫上，皿盖与对应培养皿同框拍摄。框选编号区域只用于 OCR，不改变培养皿直径标定和菌落测量区域。

后续实测分别统计“读对、读不出、读错”，尤其检查读错但看似高分的样本。修正后的编号可积累为数字识别验证资料；这次新增流程不重新训练原有 222 样本菌落边界模型。

## 用 skill / 命令行执行

`<SKILL_DIR>` 是本 skill 文件夹绝对路径。命令行与软件共用 `app/label_workflow.py` 和 `app/label_ocr.py`，因此 skill 包需保留 `app/`。完整版内置 `app/ocrlibs` 离线 OCR 组件。CLI 可读取数字候选；框选编号区域重试在软件界面。

先扫描图片：

```powershell
python "<SKILL_DIR>\scripts\number_label_workflow.py" scan `
  --folder "C:\experiment\photos" `
  --out "C:\experiment\assignments.csv"
```

按 `assets/treatment-code-template.csv` 填写 `codes.csv`，列为 `code,treatment`。编号必须按文本保留，避免电子表格把 `01` 变成 `1`。扫描得到的分配表字段为：

| 列 | 含义 |
|---|---|
| `id` | 扫描生成的图片标识，保持原值 |
| `relative_path` | 原图相对位置，供核对 |
| `code` | 本批处理编号，如 `1`、`11`、`01` |
| `replicate` | 皿上的实际重复号；未知留空 |
| `confirmed` | 核对后填 `true`；空值或 `false` 不允许直接执行 |
| `ocr_text`、`ocr_score` | 已有候选文本和分数，仅供核对 |
| `ocr_reason` | 读取建议、无法判定或失败的原因 |

填写本批对应表后，可直接离线识别并输出候选表：

```powershell
python "<SKILL_DIR>\scripts\number_label_workflow.py" suggest `
  --folder "C:\experiment\photos" `
  --mapping "C:\experiment\codes.csv" `
  --out "C:\experiment\assignments.csv" `
  --experiment-id "EXP1" --strain "层出镰刀菌"
```

`suggest` 逐张读取尚未确认的图片，不把识别结果自动设为 `confirmed=true`，读不出或多个候选时保留空白。已人工确认的分配会保留；省略实验名称、菌株参数时保留本批已有值。如果更改了对应表或明确更改批次信息，旧确认会按新配置失效，需重新核对。个别图片识别异常时继续处理其他图片，保存含失败原因的分配表并返回非零退出码；OCR 组件缺失时明确报错，可改用 `scan` 手工填写。

核对图片和对应表后，先看预览：

```powershell
python "<SKILL_DIR>\scripts\number_label_workflow.py" apply `
  --folder "C:\experiment\photos" `
  --mapping "C:\experiment\codes.csv" `
  --assignments "C:\experiment\assignments.csv" `
  --experiment-id "EXP1" --strain "层出镰刀菌" --preview
```

删去 `--preview` 即生成改名副本及清单。若用户明确要求修改原文件名，增加 `--mode rename`；默认 `--mode copy`。执行必须使用完整逐图分配表，不遗漏未确认图片、不自动补确认、不猜测重复号。CLI 输出 JSON，包含输出位置、清单位置和事务标识，失败时返回非零退出码。

撤销一次直接改名：

```powershell
python "<SKILL_DIR>\scripts\number_label_workflow.py" undo `
  --folder "C:\experiment\photos" --transaction-id "执行结果里的事务标识"
```

复制或直接改名都保留原图来源字段，清单使用确认的处理元数据。后续测量时以清单为准，不重新根据新文件名猜测药剂或重复。
